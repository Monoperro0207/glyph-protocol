# Threat Model: MCP Adapter

> Model Context Protocol (MCP) adapter converts arbitrary MCP server tools into
> Glyph glyphs. The MCP server boundary is **untrusted** — servers may be
> malicious, misconfigured, or compromised. This document classifies each
> threat using STRIDE, maps it to an existing control or test, and flags gaps.

## Scope

- **Package**: `packages/adapters/mcp` (`@glyphp/adapter-mcp`)
- **Entry points**: `glyphsFromMcpTools()`, `glyphsFromMcpClient()`
- **Trust boundary**: MCP server ↔ Glyph consumer. The adapter sits at the
  boundary; its job is to validate, classify, and constrain what the MCP server
  declares before any consumer executes it.
- **Source**: `packages/adapters/mcp/src/index.ts`

## Threats

### Spoofing

| Threat | Description | Control | Test |
|--------|-------------|---------|------|
| Tool-name collision | Two MCP servers expose tools with the same name → glyph name collision in the consumer's lexicon. | Names are converted to kebab-case via `toKebab()`. The `provider` field on the glyph card records the server identifier for disambiguation. | [Converts every MCP tool to a glyph with a kebab-case name](`../packages/adapters/mcp/test/mcp.test.ts#L37`) |
| Attacker impersonates a trusted MCP server | Consumer connects to a server at a spoofed transport address → adapter blindly trusts whatever tools the server declares. | Transport-level authentication is **out of scope** for the adapter (it receives an already-connected `McpClientLike`). The caller is responsible for transport security (TLS, auth). | Control documented; no automated test for adapter-level server identity. See `glyphsFromMcpClient` integration at [L106](`../packages/adapters/mcp/test/mcp.test.ts#L106`) for client wiring. |

### Tampering

| Threat | Description | Control | Test |
|--------|-------------|---------|------|
| Schema poisoning | Malicious MCP server returns deliberately invalid JSON Schema in `inputSchema` or `outputSchema` → input validation bypass or output contract violation. | `inputSchema` is compiled at adapt-time via `buildZodInput()` → `jsonTypeToZod()`. `outputSchema` is compiled via `compileJsonSchema()` from `@glyphp/core` (fail-fast). `outputValidation: 'schema'` (default) rejects mismatched output. | [Output matching declared MCP outputSchema validates successfully](`../packages/adapters/mcp/test/mcp.test.ts#L211`) — [Output violating declared MCP outputSchema is rejected](`../packages/adapters/mcp/test/mcp.test.ts#L220`) — [Output missing a required field is rejected](`../packages/adapters/mcp/test/mcp.test.ts#L227`) |
| Malicious annotations | MCP server sets `readOnlyHint: true` on a tool like `delete_all_records` to bypass the consumer's confirmation gate. | Dangerous tool name detection (`DANGEROUS_TOOL_WORDS` regex) overrides annotations: any tool name containing `delete`, `destroy`, `remove`, `truncate`, `exec`, `overwrite`, `wipe`, `purge`, `drop`, `write`, `update`, `kill` is classified as `danger` regardless of what annotations claim. | [A dangerous tool name overrides a lying readOnlyHint](`../packages/adapters/mcp/test/mcp.test.ts#L132`) — [A benign tool name keeps its honest readOnlyHint](`../packages/adapters/mcp/test/mcp.test.ts#L177`) |
| Input schema lacks precision | MCP server declares `inputSchema: { type: "object" }` with no properties → consumer can pass anything, bypassing all validation. | When schema is absent or has no `properties`, `buildZodInput()` returns `z.record(z.unknown())` — passthrough, documented as a risk. | [Defaults to the caution tier when there are no annotations](`../packages/adapters/mcp/test/mcp.test.ts#L66`) covers tier classification; no explicit "bare object schema" test. Gap tracked as design decision. |

### Repudiation

| Threat | Description | Control | Test |
|--------|-------------|---------|------|
| Unverifiable tool origin | No way to trace which MCP server produced a tool or executed a call. | Glyph card `provider` field records the MCP server name (defaults to `"mcp"`, overridable via `options.provider`). Execution receipts are generated by the Glyph server downstream, not by the adapter. | [Every generated card is content-addressed](`../packages/adapters/mcp/test/mcp.test.ts#L126`) verifies card integrity; provider field is populated at [L56](`../packages/adapters/mcp/src/index.ts#L41`). No explicit test for provider tracing — gap. |

### Information Disclosure

| Threat | Description | Control | Test |
|--------|-------------|---------|------|
| Sensitive annotations leak | MCP tool descriptions or annotations may contain secrets, API keys, or internal URLs that end up on the public glyph card. | Card `intent` inherits the MCP tool description verbatim. This is a **documented risk** — no automated sanitization of description text. Operators should audit tool descriptions before publishing. | [Maps the MCP description to the glyph intent](`../packages/adapters/mcp/test/mcp.test.ts#L46`) confirms description passthrough. No redaction test — controlled via documentation. |
| Handler error messages leak MCP internals | MCP tool errors include raw content blocks that may expose server internals to the consumer. | Handler throws `MCP tool "${toolName}" failed: ${text}` where text is joined from error content blocks. The error message is user-facing; MCP content is included as-is. | [Handler throws when the MCP tool result is an error](`../packages/adapters/mcp/test/mcp.test.ts#L97`) confirms error propagation. No content sanitization test — gap. |

### Denial of Service

| Threat | Description | Control | Test |
|--------|-------------|---------|------|
| Massive tool explosion | MCP server exports 1000+ tools → adapter generates 1000+ glyphs, exhausting consumer lexicon storage. | No explicit limit in the adapter. Consumers can apply their own lexicon size limits. Operation-level timeout from the MCP transport layer protects against slow listing. | No automated test for tool count limits. Control documented, tracked as future enhancement. |
| Slow tool listing | MCP server's `listTools()` hangs → consumer blocked at adapt-time. | Consumer is responsible for setting a deadline on `listTools()`. The adapter does not enforce its own timeout. | [glyphsFromMcpClient lists tools and wires handlers to callTool](`../packages/adapters/mcp/test/mcp.test.ts#L106`) tests happy path only. No timeout test — gap. |

### Elevation of Privilege

| Threat | Description | Control | Test |
|--------|-------------|---------|------|
| Overbroad passthrough | MCP tool marked `readOnlyHint: true` that actually performs writes → risk tier misclassification allows execution without confirmation. | Dangerous tool name detection (see Tampering > Malicious annotations). Risk tier is `danger` when name is dangerous or `destructiveHint` is set, `safe` when `readOnlyHint` with benign name, `caution` otherwise. | [Maps destructiveHint to a danger tier requiring confirmation](`../packages/adapters/mcp/test/mcp.test.ts#L60`) — [Maps readOnlyHint to a safe, side-effect-free cost](`../packages/adapters/mcp/test/mcp.test.ts#L52`) |
| Malicious annotations bypass confirmation | MCP server tags a destructive tool as `idempotentHint: true` and omits `destructiveHint` to avoid the confirmation gate. | `requiresConfirmation` is derived from `destructiveHint OR dangerousName`. Idempotency is separate. | [A dangerous tool name overrides a lying readOnlyHint](`../packages/adapters/mcp/test/mcp.test.ts#L132`) |
| Output validation bypass | Consumer sets `outputValidation: 'none'` → any output passes, including malicious structured content. | Opt-in escape hatch. Default is `'schema'`. Documented as unsafe — only use with fully trusted MCP servers. | [outputValidation: 'none' opts out — any output passes](`../packages/adapters/mcp/test/mcp.test.ts#L233`) |
